1. Что такое СУБД и зачем нужна
СУБД (Система Управления Базами Данных) — это программный комплекс, который обеспечивает создание, хранение, изменение и поиск данных в базе данных, а также управление доступом к ним.

Зачем нужна:

Централизованное хранение данных вместо разрозненных файлов
Обеспечение целостности данных (constraints, транзакции)
Многопользовательский доступ с разграничением прав
Поддержка ACID-свойств транзакций (Atomicity, Consistency, Isolation, Durability)
Резервное копирование и восстановление
Эффективный поиск через индексы и оптимизатор запросов
Защита от потери данных при сбоях
Типы СУБД:

Реляционные (PostgreSQL, MySQL, Oracle, MS SQL Server) — данные в таблицах
Документные/NoSQL (MongoDB) — данные в виде документов
Ключ-значение (Redis) — простые пары ключ-значение
Графовые (Neo4j) — для связанных данных
ACID кратко (часто спрашивают):

Atomicity — транзакция выполняется целиком или не выполняется вообще
Consistency — БД переходит из одного корректного состояния в другое
Isolation — параллельные транзакции не мешают друг другу
Durability — после commit данные сохранены даже при сбое
2. Чем PostgreSQL отличается от MySQL
Критерий	PostgreSQL	MySQL
Тип	Объектно-реляционная (ORDBMS)	Реляционная (RDBMS)
Лицензия	PostgreSQL License (свободная)	GPL / коммерческая (Oracle)
Соответствие SQL-стандарту	Очень высокое	Частичное
Транзакции	Полная поддержка ACID везде	ACID только в InnoDB
Типы данных	Богатый набор: JSON/JSONB, массивы, hstore, range, geometric, UUID	Меньший набор
Наследование таблиц	Поддерживается	Нет
Materialized Views	Есть	Нет (только обычные view)
Полнотекстовый поиск	Встроенный, мощный	Базовый
CTE и оконные функции	Полная поддержка	Только с MySQL 8.0+
Производительность	Лучше для сложных запросов и записи	Быстрее на простых SELECT
Ключевая фраза для собеседования: PostgreSQL — это более «академическая» и функциональная СУБД, точнее следует SQL-стандарту, а MySQL исторически проще и быстрее для веб-приложений с большим количеством простых чтений.

3. Базовые SQL-запросы
SELECT — выборка данных
sql
-- Простая выборка
SELECT name, age FROM users;

-- Все столбцы
SELECT * FROM users;

-- С условием
SELECT * FROM users WHERE age > 18;

-- С сортировкой и лимитом
SELECT * FROM users ORDER BY age DESC LIMIT 10;

-- DISTINCT — уникальные значения
SELECT DISTINCT city FROM users;
INSERT — добавление
sql
-- Одна запись
INSERT INTO users (name, age, email) 
VALUES ('Иван', 25, 'ivan@mail.ru');

-- Несколько записей
INSERT INTO users (name, age) 
VALUES ('Петр', 30), ('Анна', 22);
UPDATE — изменение
sql
UPDATE users 
SET age = 26, email = 'new@mail.ru' 
WHERE id = 1;
⚠️ Без WHERE обновятся все строки — частая ошибка, о которой важно сказать на собеседовании.

DELETE — удаление
sql
DELETE FROM users WHERE id = 5;
⚠️ То же самое: без WHERE удалятся все строки. TRUNCATE TABLE — быстрее для очистки всей таблицы, но не пишет в журнал построчно.

WHERE — фильтрация
sql
SELECT * FROM users 
WHERE age BETWEEN 18 AND 30 
  AND city IN ('Москва', 'СПб')
  AND name LIKE 'И%'      -- начинается на И
  AND email IS NOT NULL;
Операторы: =, <>, >, <, >=, <=, AND, OR, NOT, IN, BETWEEN, LIKE, IS NULL.

JOIN — соединение таблиц
sql
-- INNER JOIN — только совпадения в обеих таблицах
SELECT u.name, o.product 
FROM users u 
INNER JOIN orders o ON u.id = o.user_id;

-- LEFT JOIN — все из левой + совпадения из правой
SELECT u.name, o.product 
FROM users u 
LEFT JOIN orders o ON u.id = o.user_id;

-- RIGHT JOIN — наоборот
-- FULL OUTER JOIN — все записи из обеих таблиц
-- CROSS JOIN — декартово произведение
Визуально:

INNER — пересечение
LEFT — левый круг целиком + пересечение
RIGHT — правый круг целиком + пересечение
FULL — оба круга
GROUP BY — группировка
sql
-- Количество пользователей по городам
SELECT city, COUNT(*) AS users_count
FROM users
GROUP BY city
HAVING COUNT(*) > 10  -- фильтр после группировки
ORDER BY users_count DESC;
Важное правило: в SELECT при использовании GROUP BY могут быть только столбцы из GROUP BY или агрегатные функции (COUNT, SUM, AVG, MIN, MAX).

Разница WHERE и HAVING:

WHERE фильтрует строки до группировки
HAVING фильтрует группы после группировки
Порядок выполнения SQL (часто спрашивают): FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT

5. Схема, таблица, индекс
Схема (Schema)
Схема — это логический контейнер (namespace) внутри базы данных, который объединяет таблицы, представления, функции и другие объекты.

В одной БД может быть несколько схем — это позволяет:

Разделять объекты по назначению (например, sales, hr, analytics)
Избежать конфликта имён (можно иметь sales.users и hr.users)
Разграничивать права доступа на уровне схемы
По умолчанию создаётся схема public.

sql
CREATE SCHEMA sales;
CREATE TABLE sales.orders (...);
SELECT * FROM sales.orders;
Иерархия в PostgreSQL: Сервер → Кластер → База данных → Схема → Таблица

Таблица (Table)
Таблица — основной объект хранения данных в реляционной БД. Состоит из строк (записей) и столбцов (полей с заданным типом данных).

sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,           -- автоинкремент
    name VARCHAR(100) NOT NULL,      -- строка до 100 символов
    email VARCHAR(255) UNIQUE,       -- уникальное значение
    age INTEGER CHECK (age >= 0),    -- проверка
    created_at TIMESTAMP DEFAULT NOW()
);
Ограничения (constraints):

PRIMARY KEY — первичный ключ, уникальный идентификатор строки
FOREIGN KEY — внешний ключ, ссылка на другую таблицу
UNIQUE — значение уникально в столбце
NOT NULL — поле обязательно
CHECK — пользовательская проверка
DEFAULT — значение по умолчанию
Индекс (Index)
Индекс — это структура данных, которая ускоряет поиск по таблице. Аналог оглавления в книге: вместо чтения всех страниц можно найти нужную по содержанию.

sql
CREATE INDEX idx_users_email ON users(email);
CREATE UNIQUE INDEX idx_users_login ON users(login);
Плюсы: ускоряет SELECT, JOIN, WHERE, ORDER BY. Минусы: замедляет INSERT, UPDATE, DELETE (индекс надо обновлять); занимает место на диске.

Типы индексов в PostgreSQL (отличие от MySQL — спросят с большой вероятностью):

B-tree — по умолчанию, для =, <, >, BETWEEN, ORDER BY
Hash — только для равенства (=)
GIN — для полнотекстового поиска, JSONB, массивов
GiST — для геоданных, диапазонов
BRIN — для очень больших таблиц с упорядоченными данными
SP-GiST — для непересекающихся данных
Когда индекс не нужен: на маленьких таблицах, на столбцах с малым числом уникальных значений (например, пол), на столбцах, которые часто обновляются.

Совет: проверять использование индекса можно через EXPLAIN ANALYZE — это команда, которую обязательно стоит упомянуть на собеседовании.

Если хочешь, могу дальше углубиться в любую тему — например, типы JOIN с диаграммами, нормализацию, или сразу переходи к следующему вопросу.

Навигация и работа с файлами
ls — список файлов в директории.

ls -l — подробный вывод (права, владелец, размер, дата)
ls -a — показать скрытые файлы (начинаются с точки)
ls -la или ls -lah — всё вместе + размеры в человекочитаемом виде (KB, MB)
cd — переход в директорию.

cd /var/log — абсолютный путь
cd .. — на уровень выше
cd ~ или просто cd — в домашнюю папку
cd - — в предыдущую директорию
pwd — показать текущую директорию (могут спросить вместе с cd).

mkdir — создать директорию.

mkdir mydir — одна папка
mkdir -p /home/user/a/b/c — создать вложенные папки сразу (флаг -p важен)
rm — удалить.

rm file.txt — файл
rm -r folder/ — папку рекурсивно
rm -rf folder/ — рекурсивно и без подтверждения ⚠️ Важно сказать: rm -rf / удалит всё в системе. На собеседовании ценят, когда упоминают про осторожность.
cp — копировать.

cp file.txt /tmp/ — файл
cp -r folder/ /tmp/ — папку рекурсивно
mv — переместить или переименовать.

mv old.txt new.txt — переименование
mv file.txt /tmp/ — перемещение
Просмотр и поиск в файлах
cat — вывести содержимое файла целиком.

cat file.txt
cat file1 file2 > merged.txt — объединить файлы
grep — поиск по содержимому.

grep "error" log.txt — найти строки со словом
grep -i "error" log.txt — без учёта регистра
grep -r "TODO" /project — рекурсивно по папке
grep -v "info" — инверсия (всё, кроме строк с "info")
grep -n — с номерами строк
Часто комбинируют: cat log.txt | grep "ERROR"
tail — конец файла (часто для логов).

tail file.log — последние 10 строк
tail -n 50 file.log — последние 50 строк
tail -f file.log — «живой» режим, выводит новые строки по мере появления (классика для логов PostgreSQL)
head — начало файла, парная команда (могут спросить).

head -n 20 file.log — первые 20 строк
nano — простой текстовый редактор.

nano file.txt — открыть/создать
Ctrl+O — сохранить, Ctrl+X — выйти, Ctrl+W — поиск
⚠️ Стоит упомянуть, что есть vim (мощнее, но сложнее) — этот вопрос часто всплывает.

Управление сервисами — systemctl
systemctl — управление systemd (стандарт в современных Linux). Очень важно для DBA: PostgreSQL запускается и работает как сервис.

bash
sudo systemctl start postgresql       # запустить
sudo systemctl stop postgresql        # остановить
sudo systemctl restart postgresql     # перезапустить
sudo systemctl reload postgresql      # перечитать конфиг без рестарта
sudo systemctl status postgresql      # статус (running/dead/failed)
sudo systemctl enable postgresql      # автозапуск при загрузке
sudo systemctl disable postgresql     # отключить автозапуск
systemctl is-active postgresql        # активен ли сейчас
systemctl list-units --type=service   # все запущенные сервисы
Что могут спросить:

Разница между restart и reload: restart останавливает и заново запускает процесс, reload только перечитывает конфигурацию (без разрыва соединений).
Разница между enable и start: start — запустить сейчас, enable — настроить автозапуск при загрузке системы. Часто используют вместе: systemctl enable --now postgresql.
Просмотр процессов
ps — снимок процессов в данный момент.

ps aux — все процессы всех пользователей с подробностями (запоминается как «ps aux»)
ps -ef — то же самое, другой формат
Часто в связке: ps aux | grep postgres — найти процессы PostgreSQL
Колонки ps aux: USER, PID, %CPU, %MEM, VSZ, RSS, STAT, START, TIME, COMMAND — стоит знать, что PID это идентификатор процесса.

top — интерактивный мониторинг в реальном времени (CPU, память, процессы).

Обновляется каждые несколько секунд
q — выход, k — убить процесс по PID, M — сортировать по памяти, P — по CPU
htop — улучшенная версия top с цветным интерфейсом (часто спрашивают, знаешь ли).

kill — завершить процесс по PID.

kill 1234 — мягкое завершение (SIGTERM)
kill -9 1234 — принудительное (SIGKILL), когда процесс не отвечает
pkill postgres — убить по имени
Что ещё стоит знать (часто спрашивают рядом)
Права доступа — chmod, chown:

bash
chmod 755 file.sh         # rwx для владельца, rx для остальных
chmod +x script.sh        # сделать исполняемым
chown postgres:postgres file.txt   # сменить владельца
Числовая запись прав: r=4, w=2, x=1 → 7=rwx, 5=rx, 4=r. То есть 755 = владелец rwx, группа rx, остальные rx.

Перенаправление и пайпы:

bash
command > file       # вывод в файл (перезапись)
command >> file      # дозапись
command 2> err.log   # перенаправить ошибки
command1 | command2  # передать вывод первой команде на вход второй
Полезно для DBA:

bash
df -h              # свободное место на дисках
du -sh /var/lib/postgresql   # размер папки
free -h            # оперативная память
journalctl -u postgresql -n 100   # логи сервиса через systemd
Топ-вопросы, которые реально задают джуниору
Как посмотреть последние строки лога в реальном времени? → tail -f /var/log/postgresql/postgresql.log
Как найти все процессы PostgreSQL? → ps aux | grep postgres
Как перезапустить PostgreSQL? → sudo systemctl restart postgresql
Как проверить, запущен ли сервис? → systemctl status postgresql
Чем kill отличается от kill -9? → SIGTERM (мягко) vs SIGKILL (жёстко).
Как найти ошибки в логе? → grep -i "error" /var/log/postgresql/postgresql.log
Как посмотреть свободное место на диске? → df -h (важно для DBA — часто базы съедают всё место).
